# AgriOps MCP — ユーザーペルソナと体験設計

## ペルソナ一覧

---

### Persona 1: 田中 誠一（55 歳）— 農業派遣マネージャー

**プロフィール**
- 鹿児島の農業人材派遣会社で 30 名のスタッフを管理
- 日々 10〜20 の圃場へスタッフを割り振り、天候による当日変更が多い
- ITスキル: Excel はできるが、複数アプリの切り替えが苦手

**現在使っているサービス**
| サービス | 用途 | 不満 |
|---------|------|------|
| tenki.jp / ウェザーニュース | 天気確認 | 圃場単位ではない。市区町村レベルで粗い |
| Excel + 紙の配置表 | スタッフ配置 | 天候変更のたびに手動修正。共有が遅い |
| 電話 / LINE グループ | 現場連絡 | 情報が流れる。履歴が残らない |
| JA の営農カレンダー（紙） | 作期確認 | 年 1 回更新。リアルタイム性ゼロ |

**ペインポイント**
1. 朝 5 時に起きて tenki.jp→圃場リスト→電話の 3 ステップを毎日繰り返す
2. 「雨降るの？降らないの？」の判断に 30 分かかる
3. 農薬散布日と収穫日の間隔（残留期間）を手動計算している

**AgriOps で実現する次世代体験**
> **「朝起きたら、今日の最適配置が届いている」**
- `daily_briefing` → 全圃場の天候サマリ＋リスクフラグを 1 画面で
- `spray_window` → 散布可能時間帯を自動判定、現場に即共有
- `field_weather_report` → 圃場単位の統合レポートで「この圃場は今日 OK」が一目で分かる

### Persona 2: 山本 あゆみ（32 歳）— JA 営農指導員

**プロフィール**
- JA 鹿児島の営農指導部門。担当農家 80 戸、週 15〜20 件の圃場訪問
- 品種選定・防除計画・収穫時期の助言が主業務
- ITスキル: スマホネイティブ世代。タブレットで農薬検索は日常

**現在使っているサービス**
| サービス | 用途 | 不満 |
|---------|------|------|
| FAMIC 農薬登録情報提供システム | 農薬適用確認 | UI が古い。作物×病害虫のクロス検索が遅い |
| eMAFF 筆ポリゴン / 地理院地図 | 圃場特定 | GIS の知識がないと使いこなせない |
| 気象庁 防災情報 | 警報確認 | 県単位で粗い。圃場レベルの判断ができない |
| JA 独自の営農管理システム | 訪問記録 | データが閉じている。AI連携不可 |

**ペインポイント**
1. 訪問前に 4 つのサイトを開いて情報を手動集約する（30 分/件）
2. 「この農薬、この作物に使えますか？」の即答に自信が持てない
3. 収穫適期の助言が経験則頼み。天候変動への対応が後手に回る

**AgriOps で実現する次世代体験**
> **「訪問先の圃場 ID を 1 つ伝えるだけで、全データが揃う」**
- `field_visit_checklist` → 圃場の基本情報・天候・農薬候補・リスクを訪問前にワンタップで生成
- `pesticide_advice` → FAMIC 登録に基づく即答。残留日数・ローテーション込み
- `harvest_readiness` → 天候＋農薬安全期間の両面から「収穫 OK」を判定

### Persona 3: 鮫島 隼人（42 歳）— 中規模さつまいも農家

**プロフィール**
- 鹿児島県で 3 ha のさつまいも＋茶を経営。従業員 2 名
- 「紅はるか」のブランド化に注力。品質管理に厳格
- ITスキル: スマホでの LINE・YouTube は使うが、PC は苦手

**現在使っているサービス**
| サービス | 用途 | 不満 |
|---------|------|------|
| tenki.jp | 天気 | 自分の畑ピンポイントではない |
| YouTube / 農家仲間 | 栽培技術 | 断片的。体系的な知識にならない |
| 手帳 / ノート | 農作業記録 | 検索できない。翌年の参考にしにくい |
| JA の定期巡回 | 専門助言 | 月 1〜2 回。タイミングが合わない |

**ペインポイント**
1. 「今日畑に水やったほうがいい？」の判断を勘でやっている
2. 農薬散布のタイミングで悩む（風が強い日に撒いて近隣トラブル）
3. 収穫時期の見極めがブランド価値に直結するが、根拠が弱い

**AgriOps で実現する次世代体験**
> **「畑のことを聞けば、AIが根拠ごと答えてくれる」**
- `crop_calendar` → さつまいもの作期カレンダーが手元に
- `irrigation_schedule` → ET₀ に基づく「今日は○○リットル灌水」の具体指示
- `spray_window` → 「明日の午前 6〜9 時が散布ベスト」と風速根拠で提案
- `harvest_readiness` → 「あと 3 日待てば最適。理由: 降雨後の乾燥不足」

### Persona 4: 佐藤 リナ（28 歳）— AgriTech スタートアップ CTO

**プロフィール**
- 東京のスタートアップで農業 DX アプリを開発中
- ドローン画像解析＋圃場管理の SaaS を構築中
- ITスキル: フルスタックエンジニア。API 設計に強い

**現在使っているサービス**
| サービス | 用途 | 不満 |
|---------|------|------|
| Open-Meteo API | 天気データ | 農業特化の指標（ET₀、土壌）は自前計算 |
| eMAFF データダウンロード | 筆ポリゴン | GeoJSON を自前パース。更新検知が手動 |
| FAMIC Web サイト | 農薬データ | API がない。スクレイピングが必要 |
| 気象庁 XML | 警報データ | パースが複雑。キャッシュ管理が面倒 |

**ペインポイント**
1. 4 つのデータソースを統合するアダプタ層だけで 2 ヶ月かかった
2. MCP 対応したいが、プロトコル実装にリソースを割けない
3. 顧客の農家に「AIアドバイス」を提供したいが、プロンプト設計のノウハウがない

**AgriOps で実現する次世代体験**
> **「MCP の URL を 1 つ繋ぐだけで、日本の農業データ基盤が手に入る」**
- Streamable HTTP (`/mcp`) で自社アプリに組み込み
- `outputSchema` 付きツールで型安全なデータ取得
- Server Card で機能の自動検出 → 自社 AI エージェントに即統合

## 競合・代替サービスとの差別化

| 既存サービス | 強み | AgriOps の優位性 |
|------------|------|-----------------|
| ウェザーニュース for Business | 高精度天気 | MCP プロトコルで AI エージェント統合。圃場×農薬×警報のクロス分析 |
| アグリノート（ウォーターセル） | 圃場管理 UI | オープンソース + MCP 標準。ベンダーロックインなし |
| KSAS（クボタ） | 機械連携 | 機械メーカー非依存。データポータビリティ |
| xarvio (BASF) | AI 病害虫予測 | 日本の FAMIC 登録データに直接アクセス。国内法規に準拠 |
| 農薬ナビ | 農薬検索 | MCP ツールとして AI が直接呼び出せる。プロンプト統合 |
