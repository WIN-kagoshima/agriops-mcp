## 1. Submission shape (decision)

**AgriOps MCP submits as an anonymous, read-mostly Streamable HTTP remote MCP server.**

Rationale:

- All default-tier data (eMAFF farmland, Open-Meteo weather, JMA warnings, FAMIC pesticide registrations) is public open data. There is no user account, no paid quota, and no private data behind the default 8-tool surface.
- The one non-read-only default tool, `create_staff_deploy_plan`, has `sideEffect: "draft"` — it returns a non-committed plan for the user to review, never sends or commits anything itself. No `destructiveHint` tool is in the default surface.
- Per the Directory docs, user-consent OAuth 2.1 + PKCE is **required only for servers that touch user accounts, paid quotas, or private data**. The default surface touches none of those, so we do not build a PKCE flow just to satisfy the checklist. The existing OAuth Client Credentials demo (Phase 4, `src/auth/oauth-client.ts`) stays a self-hosted/demo feature, not the Directory's authentication path.
- If a future paid tier (WAGRI, Phase 7+ per [AGENTS.md](../AGENTS.md)) is added, it will require real user-consent OAuth 2.1 + PKCE + RFC 7591/8414/9728 discovery at that time, in a way that does not touch the anonymous default surface — this is the "convergence over choice" principle: one adapter interface, not two servers.

## 2. Endpoint

The listing endpoint is a dedicated, deliberately anonymous Cloud Run service — separate project
(`mcp-service-492010`), separate service account, same unmodified server image as the operational
deployment. This keeps the IAM-protected operational service (`README.md`) untouched while giving
Anthropic's reviewer (and any MCP registry crawler) an endpoint that never requires credentials:

```text
https://agriops-mcp-public-731026511067.asia-northeast1.run.app/mcp
```

Built and deployed reproducibly via [`cloudbuild.public.yaml`](../cloudbuild.public.yaml) and
[`.github/workflows/deploy-public.yml`](../.github/workflows/deploy-public.yml) — `gcloud run deploy
--allow-unauthenticated`, real eMAFF/FAMIC snapshots baked from a GCS snapshot bucket (not the unit-test
fixtures), the default 8-tool surface only (`AGRIOPS_ENABLE_EXTENDED_TOOLS` /
`AGRIOPS_ENABLE_LEGACY_TOOLS` never set), and the same per-IP rate limiting
(`src/server/rate-limit.ts`) and `AGRIOPS_ALLOWED_HOSTS` Host/Origin allowlisting as the operational
deployment. See [SECURITY.md](../SECURITY.md#hardening-notes-for-operators) for the full posture.

A static fallback snapshot of this same default surface is committed at [`.well-known/mcp-server.json`](../.well-known/mcp-server.json) (generated by `npm run snapshot:well-known`), so a reviewer or registry crawler that only clones the GitHub repo — without hitting the live endpoint — still sees the contract.

## 3. Default surface for review

With `AGRIOPS_ENABLE_EXTENDED_TOOLS` and `AGRIOPS_ENABLE_LEGACY_TOOLS` unset (the default since `1.12.0`), the endpoint advertises exactly 8 model-visible tools:

`get_weather_1km`, `get_weather_warning`, `search_farmland`, `area_summary`, `nearby_farms`, `get_pesticide_rules`, `create_staff_deploy_plan`, `open_dashboard`.

This keeps the reviewer's functional test (one call per tool, per the [pre-submission checklist](https://claude.com/docs/connectors/building/review-criteria)) to 8 tools instead of ~30, and matches the "aim for ~7 model-visible tools" guidance already in [`.cursor/rules/03-mcp-tool-rules.mdc`](../.cursor/rules/03-mcp-tool-rules.mdc). See [`tests/conformance/directory-surface.test.ts`](../tests/conformance/directory-surface.test.ts) for the automated pin of this set.

## 8. Phase 4 local verification log (2026-07-16)

This section records what was actually run locally ahead of the live-endpoint / Claude Desktop pass, and the two environment gotchas hit along the way, so the next person (or CI) doesn't re-debug them.

### 8.1 Default surface, confirmed via Inspector

With `EMAFF_SNAPSHOT_PATH` / `FAMIC_SNAPSHOT_PATH` pointed at real (or fixture) SQLite snapshots, `tools/list` against `dist/server.js --stdio` returns exactly **18 tools**: the **8 model-visible default tools** (`get_weather_1km`, `get_weather_warning`, `search_farmland`, `area_summary`, `nearby_farms`, `get_pesticide_rules`, `create_staff_deploy_plan`, `open_dashboard`) plus **10 `ui/visibility: ["app"]`** helper tools the dashboard uses internally. This matches §3 exactly.

`tools/call` was exercised for all 8 default tools (weather, warnings, farmland search/summary/nearby, pesticide rules, deploy-plan draft, dashboard open) — every call returned `isError: false`. Empty-result responses (e.g. `search_farmland` on a 5-row fixture snapshot) are expected with fixture data, not failures; what matters for the checklist is that no tool throws, times out, or returns a malformed shape.

### 8.2 Two non-obvious local-environment gotchas

- **`EMAFF_SNAPSHOT_PATH`/`FAMIC_SNAPSHOT_PATH` default to relative paths** (`./snapshots/...`, see `src/lib/config.ts`), resolved against the *server process's* CWD at `existsSync` time — not the repo root. If you `cd` elsewhere before spawning `node dist/server.js` (e.g. to work around the Inspector bug below), pass **absolute** paths via `EMAFF_SNAPSHOT_PATH` / `FAMIC_SNAPSHOT_PATH` env vars rather than relying on the default.
- **`@modelcontextprotocol/inspector@0.22.0`'s `--cli` mode has an upstream CWD-resolution bug**: `cli/build/index.js` does `fs.existsSync("../package.json")` (relative to `process.cwd()`, not `__dirname`) to decide whether it's running as the standalone `inspector-cli` package or bundled inside `inspector`; if a stray `package.json` happens to exist one directory above wherever you invoke the command from, it takes the wrong branch and crashes with `Cannot find module '.../cli/package.json'`. Workaround: invoke from a scratch directory (e.g. `/tmp/inspector-run`) with no `package.json` one level up, and use absolute paths for everything else. This does not affect the GitHub Actions CI runner (whose CWD parent has no stray `package.json`), so the CI hard gate added in Phase 3 is unaffected — this is purely a local-machine footgun.

### 8.3 MCP Apps screenshot recipe (used for the 3 sample captures)

Real screenshots for the submission portal should come from a genuine host (Claude Desktop / MCP Inspector's Apps preview) connected to the live server. For local iteration without a live host, the same `dist/ui/dashboard.html` can be driven standalone by injecting a mock bridge in the browser console before interacting with the UI:

```js
window.mcpApps = {
  callTool: async (name, args) => {
    // return { content: [...], structuredContent: { ...withVizHint... } }
    // shaped per src/lib/viz-hint.ts for the view you want to demo
  },
  setView: () => {},
  onStateChange: () => () => {},
};
```

Then interact with the prefecture selector / quick-action buttons as a user would — the dashboard calls `window.mcpApps.callTool` on every navigation, so each click renders a new view with the injected data. This validated `bar_compare`, `radar`, and `choropleth` (maplibre-gl + OSM tiles) all render correctly post the React 19 pinning fix in `package.json`. Final submission screenshots should still be recaptured against a live connection per the note in §6 (screenshots are uploaded through the portal, not committed to the repo).

## 9. 2026-07-22 UX & spec-compliance pass

A follow-up pass focused on user experience, artifact portability, and closing latent surface-consistency gaps found while re-reading the current MCP spec and Directory review criteria against this codebase:

- **`AGRIOPS_ALLOWED_HOSTS`** (`src/lib/config.ts`, `src/server/transport-http.ts`): the Streamable HTTP DNS-rebinding host allowlist previously only trusted `MCP_BASE_URL`'s own host. Cloud Run exposes both a stable custom domain (if configured) and its own per-revision `*.run.app` URL; a request arriving on the second host was rejected with `421` even though the service was otherwise reachable — the root cause of the "live endpoint reachable anonymously" gap tracked in §4. `AGRIOPS_ALLOWED_HOSTS` (comma-separated, no scheme) lets an operator list additional trusted hostnames.
- **Dashboard/tool-surface consistency**: the AgriOps Dashboard MCP App (`ui://agriops/dashboard.html`) and several prompts (`strategy_room_dashboard`, `market_trend_briefing`, ...) called five tools (`get_municipality_stats`, `get_labor_shortage_stats`, `get_ssw_crop_compatibility`, `get_livestock_regional_stats`, `get_market_price`) that simply did not exist on the default 8-tool surface, because they were entirely gated behind `AGRIOPS_ENABLE_LEGACY_TOOLS`. A Directory reviewer opening the dashboard with no env flags set would have hit "tool not found" on every quick-action click. Fixed by registering these five tools **unconditionally**, but with `_meta["ui/visibility"] = ["app"]` when the legacy flag is off — the same LLM-invisible-but-UI-callable pattern already used for the Phase 5 app-only helpers. `.well-known/mcp-server.json` and `src/server/well-known.ts` were updated to report each tool's *runtime* visibility (`RegisteredSurface.appOnlyToolNames`) rather than only the static catalog entry, so the Server Card doesn't claim these are model-visible when they aren't. Prompts that need extended/legacy-only tools are now gated behind the same flags, and `strategy_room_dashboard` degrades its tool-call instruction gracefully (falls back to "just open the dashboard") when the flag combination it needs isn't set. Covered by `tests/conformance/directory-surface.test.ts`.
- **`create_staff_deploy_plan` `outputSchema`**: the tool previously had no `outputSchema`, despite every other default-tier tool having one. Added, covering both the successful-draft and Form-elicitation-declined response shapes.
- **Portable output artifacts** (the main UX ask behind this pass — "take this artifact home"): `search_farmland` and `nearby_farms` now embed a GeoJSON `FeatureCollection` resource block; `get_pesticide_rules` and `create_staff_deploy_plan` now embed a CSV resource block (RFC 4180, shared serialiser in `src/lib/csv.ts`). These use the MCP Spec §6.4 `EmbeddedResourceSchema` shape (inline `resource` content block, not a `resource_link` the client would have to fetch separately) since the data is generated per-call and has no stable URI. Purely additive — clients that don't render embedded resources just ignore the extra content block. See `src/lib/artifacts.ts`, `tests/conformance/artifacts.test.ts`.
- **Dashboard CSV export button**: the dashboard header gained a "CSV ダウンロード" button that serialises whatever tabular data is currently rendered (any `viz_hint` with a `dataPath` array, or the DataTable fallback) into CSV client-side and triggers a browser download. Per "Interoperability over optimization," some MCP Apps hosts sandbox the iframe in a way that silently drops anchor-click downloads, so the same click also opens a read-only textarea with a "コピー" (copy) button as a working fallback. See `src/ui/csv-export.ts`.
- **Icon and screenshots**: see the checklist table above (§4) — `assets/logo.png` was a mislabeled JPEG, now a true PNG; 5 dashboard screenshots captured via the new `npm run capture:screenshots` script.

## 10. What we deliberately did not do

- **No server split.** One adapter-based server, gated tool tiers — not `agriops-core` + `agriops-ops`. Matches "convergence over choice."
- **No OAuth 2.1/PKCE build-out for the default surface.** Not required for an anonymous public-data connector; would add complexity with no reviewer benefit at this tier.
- **No removal of the extended/legacy tools.** They are real, tested, still-published features, gated by an opt-in env var — see [AGENTS.md](../AGENTS.md) and [docs/architecture.md](architecture.md#tool-surface-tiers-since-1120).
