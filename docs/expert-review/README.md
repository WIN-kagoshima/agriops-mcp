## 使い方

1. 上記 **3 ファイル**をレビュアーに渡す（または PDF 化する）。
2. 下の **「統合評価プロンプト」**をそのままコピペし、ChatGPT / Claude 等に貼る。あわせて 3 資料の本文を添付するか、リポジトリの `docs/expert-review/` を参照させる。

## 統合評価プロンプト（コピペ用）

```
あなたは技術・アーキテクチャ・農業ドメイン・プロダクトのいずれにも触れられるシニアレビュアーです。これから AgriOps MCP（v1.10.2）について、添付の 3 資料を読んだうえで一括評価してください。資料は (1) アーキテクチャ・MCP・OSS (2) 農業統計・SSW・倫理 (3) 戦略室 UI・導入・価値、の順です。

【A. 技術・MCP・OSS】箇条書き「結論 → 根拠」で答えること。
- viz_hint（structuredContent 拡張）の設計の妥当性、将来のブレークリスク、標準化のあり方
- TopoJSON を MCP リソースと app-only fetch の二系統で扱う是非（保守・セキュリティ・性能）
- MCP Apps 単一 HTML 制約下での MapLibre + 自前 SVG の選択は妥当か、代替があれば短く
- OSS として初見コントリビュータが迷う点を 3 つ、改善案つき
- 公開ツール surface・リソース・CSP・依存で気になる点

【B. ドメイン・データ・SSW】批判的かつ建設的に答えること。推測は推測と明記。
- 農林業センサス・畜産統計・市町村内蔵 DB を「派遣優先度」の物語に接続するときの、統計上の誤読・比較不可能な点（定義・口径に触れる）
- ブロイラー捕鳥と SSW の「相性」を強調する表現について、労務・衛生・教育・福祉の注意点と、プロダクトに必要な注釈の書き方案
- 市町村データが網羅でないことの、UI/ドキュメント上の必須要件を 5 つ
- 追加すべき公開データを 3 つ（どの機能に直結するか一言ずつ）

【C. プロダクト・UX・導入】
- 強み 3 つ（なぜ課金・継続利用に結びつくか、証拠＝資料のどこに基づくか）
- 致命的弱点または誤解ポイント 3 つ（対策つき）
- 10 分デモのおすすめ画面順（ステップごとに一言フック）
- 最初の 90 日で追う指標を 5 つ（定義つき）

【D. ひらめき】
- この「公開データ横断 × MCP × 埋め込み戦略 UI」のパターンを、農業以外のどの業界・どの課題に当てはめると最も価値が出るか、1 アイデアだけ具体化（誰が・何が良くなるかを 4 行以内）

出力は見出し A/B/C/D で区切り、全体で長すぎないよう簡潔に。綺麗事より実務的な指摘を優先してください。
```
