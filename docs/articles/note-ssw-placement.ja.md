# 特定技能派遣の配置判断は、なぜいつも「電話」と「経験」に頼っていたのか

## 配置判断の現場で起きていること

特定技能の農業スタッフを、どの農家に、いつ配置するか。この判断は、今もベテラン担当者の頭の中にある「土地の勘」に支えられている。

- この農地は今、何を作っていたか
- 今週末の天気は作業に向いているか
- この作物に使える農薬の登録は切れていないか
- 近隣にほかの配置先はあるか（移動の効率）

これを一件ずつ、農地台帳・気象庁のページ・農薬登録DBを行き来して確認する。ベテランなら数分、新人なら小一時間かかる。しかも情報源が3つ以上に分かれているので、「確認したつもり」が起きやすい。

## AgriOpsが変えるのは「調べる時間」

AgriOps MCPは、この確認作業をAIアシスタント（Claude等）に直接聞けるようにする仕組みだ。難しい言葉で言うと「MCP（Model Context Protocol）サーバー」だが、現場の人にとって大事なのは中身より結果:

> 「鹿児島県薩摩川内市のさつまいも農地で、今週末の天気と、使える農薬を教えて」

これをAIに投げると、農地台帳（eMAFF）・気象庁の1kmメッシュ予報・農薬登録情報（FAMIC）を裏側で自動的に検索して、まとまった答えを返す。3つのサイトを開いて、住所をコピペして、目視で照合する時間がゼロになる。

## 何が公的データで、何が独自の判断か

ここは意図的に分けている。AgriOpsが返すのは**公的な生データ**（農地の場所・面積・登録作物、気温・降水量、農薬の登録内容と使用制限）で、「配置すべきか」という**最終判断は人間がする**。

理由は単純で、配置判断には土地の勘・スタッフの適性・雇用主との関係性など、データに乗らない情報が必ず絡む。AIが自動で決めるのではなく、判断に必要な「調べる時間」だけを引き受ける、という役割分担にした。

## 実際に使うと変わること

| 作業 | Before | After |
|---|---|---|
| 農地の場所・作物確認 | 台帳サイトで住所検索、目視確認 | チャットで住所か地名を伝えるだけ |
| 天気確認 | 気象庁サイトで地点検索 | 同じ会話の中で聞ける |
| 農薬の適法性確認 | FAMICのDBを検索、対象作物を確認 | 同じ会話の中で聞ける |
| 配置案のドラフト | 手作業でスプレッドシート作成 | ドラフトを自動生成（最終確認は人が行う） |

## 技術的な裏側（興味がある人向け）

エンジニア向けの技術記事はZennに書いた:「[農業の公的データをMCPの7つのプリミティブで接続する](https://zenn.dev)」。ソースコードは全部公開している（Apache-2.0ライセンス）ので、自社のシステムに組み込みたいSIerやAgriTech企業は自由に使ってもらって構わない。
